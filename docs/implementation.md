# 实现说明：可信调度、隔离执行、冻结证据、离线评分

## 当前系统结构

任务定义 → 可信主机读取任务与私有判据 → `public_input()` 导出白名单 → 独立智能体环境运行多会话 → 主机采集文件与原生轨迹 → 冻结证据 → A/B/C 离线评分 → 比较。当前工程验证在控制测试与完整选型矩阵通过后冻结条件，再执行留出集；独立人工复核是另一个保留的选型流程。

Inspect AI 是调度和日志底座。桥接层为每道题建立 Sample，外部 solver 调用模拟器或真实适配器，再由规则 scorer 保存 A 版结果。Inspect 配置中的 `mockllm/model` 是未被调用的占位，因为真正的模型属于外部智能体；它既不把真实运行变成模拟，也不使模拟运行变成真实。判断来源以 EvidenceBundle 的 provenance 和实际运行记录为准。

## 公共数据模型

| 模型 | 关键字段及用途 |
|---|---|
| TaskSpec | id、ability、family、split、sessions、initial_files、budget、memory_policy |
| SessionSpec | id、prompt、final；必须且只能最后一轮标 final |
| PrivateRubric | task_id、criteria；永不导出给被测智能体 |
| Criterion | 类型、文件路径、预期值、说明、critical 标记 |
| EvidenceBundle | 运行身份、任务、智能体、来源、状态、模型身份、事件、前后文件、可观察记忆、用量、耗时、校验和 |
| ScoreResult | 对应运行与证据校验和、评分逻辑指纹、评分器版本、逐项判定、总体判定、裁判模型、用量与错误 |

模型拒绝未知字段，并检查相对路径、重复会话/事件ID等约束。TaskSpec 中 ability、family、split 是可信调度信息；`public_input()` 只返回 sessions、initial_files、budget，不能直接序列化完整 TaskSpec 作为提示。

任务目录与rubric目录物理分开。这个目录布局本身不是访问控制，真实适配器还必须禁止挂载仓库、数据根目录、rubrics、simulation 和用户真实profile。

## 数据集接口

- `load_dataset(root, split=None)`：root 可为项目目录或data目录，返回按ID排序的 `(TaskSpec, PrivateRubric)` 列表。
- `validate_dataset(root)`：返回数量、各split/能力统计、场景族和errors，不调用智能体。
- `pilot_tasks(root)`：每能力dev前2题，共12题。

当前60题全部原创，60个不同场景族；dev每能力4题，selection和holdout每能力各3题。它们是短程微型任务，有明确的输入、规则和文件产物，并不是数月真实历史的等价物。所谓“长期”在首版主要指跨新会话的持久化使用，应在报告中准确说明。

模拟fixture只包含人工编写的预期文件状态和模拟说明；不得把fixture或rubric传给真实智能体。3道题有补充语义判据，未配置真实裁判时不伪造结论。

## 执行与证据

每个真实实验主体使用新建的临时目录。容器只挂载该主体目录，以非root用户、只读根文件系统、资源限制和固定本地镜像运行。当前适配器不会自动拉取缺失镜像。主机在容器退出后采集交付文件，不以智能体口头宣称的文件状态作真值。

新会话保留被测系统允许的原生长期记忆，清除即时聊天上下文；历史搜索、用户档案、文件记忆等通道必须明确记录。只改session ID无法证明这些通道全部隔离。不可观察的记忆保持 unknown，不能据此得出“已删除”“从未存储”等结论。

schema 2 分开记录文件类型清单与文本内容：`file_inventory_after/complete` 用于存在/缺失判定，`files_after/complete` 描述可采集文本。二进制或超大内容可以不进入文本快照，但已完整枚举的路径仍然存在；显式不完整目录清单不能被完整文本标志覆盖。旧 schema 1 证据保留原哈希算法。采集的字节、枚举项数、耗时和原生输出均有上限，详见 [适配器说明](agent-adapters.md)。

`native_session` 与 `native_tool_report` 是被测进程自报，网关 tool call 是模型提案，均不升级为独立的 `action/tool_call` 执行证据。当前适配器保持 `actions_complete=false`；动作缺失或成功必须有足够的可信观察，不能从聊天文本推断。

EvidenceBundle 分为 `simulated` 与 `real`。运行状态包括 completed、task_failed、budget_exhausted、infrastructure_error、execution_unknown。基础设施错误与执行未知不会计成智能体能力失败。正式基准无法确认预算执行时应停止或标记未知；单独的集成诊断不能冒充正式完成。

证据通过规范化序列化的 SHA-256 校验和冻结。评分前重新校验，避免改了文件或轨迹却沿用原分数。哈希能发现修改，不是签名，也不能证明证据一定来自某台机器；真实来源仍依赖采集与实验记录。

每份评分另保存 `scoring_fingerprint`，绑定当时的私有判据、`scorers.py`、`provider.py`、`models.py` 源码及裁判系统提示。它用于识别评分协议是否变化；实际请求和返回的模型身份仍单独记录，不能由源码指纹代替。

## 三种评分的实际行为

| 版本 | 行为 | 未知项处理 |
|---|---|---|
| A | 文件存在/缺失、文本、JSON、CSV和已记录动作规则 | 语义项不判；不完整观察不推断否定事实 |
| B | 全部判据交给显式配置的模型裁判 | 配置缺失、格式错误或引用不存在时明确报错或未判定 |
| C | 客观项采用A规则，语义项调用模型裁判 | 不覆盖已有客观规则；语义未知不会自动变成通过 |

纯文本 `text_equals` 逐字符比较，包括末尾换行；相关13题已在第一会话明确不附加末尾换行。JSON按完整内容比较，拒绝把布尔true等同数字1；CSV按二维字符串表格比较，包含表头。不同格式的严格程度必须在出题时说明，后续人工审查可决定是否修改协议，而不是评分后偷偷放宽。

每个判据可为 pass、fail、undetermined。当前总体规则是任一fail则fail，全部pass才pass，否则undetermined。不要把undetermined当作0分失败，也不要从失败总体反推每条判据都错。

## 模型服务与配置

JudgeProvider 支持 OpenAI兼容的 chat_completions 与 responses 两种JSON接口风格；地址不允许包含用户名、密码、查询参数或片段。配置读取只接受显式环境变量，不发现或提取其他应用凭据。

裁判系统提示明确将证据内容视为数据，不执行其中的命令。裁判没有工具；返回必须覆盖每条要求，并引用真实存在的证据ID。引用合法只是必要条件，不证明语义判断正确，还需独立人工校准。

请求模型名与返回模型名分别记录；返回名或用量缺失时保留null。接口错误不记录原始HTTP响应体或密钥。允许重试的429/5xx最多三次尝试；上下文过长、鉴权错误等明确不可重试状态不会重复请求，传输失败因送达状态不明也不自动重试。用量逐次聚合，任一尝试缺少回执时对应总量保持未知。Responses 必须有合法 completed 终态；HTTP 200 或正文里出现 JSON 都不能掩盖 failed/incomplete。

当前CLI真实运行和离线裁判都从 KMB_BASE_URL/KMB_API_KEY/KMB_MODEL/KMB_API_STYLE 读取各阶段上游配置。真实运行在宿主建立每次试验独立的TrialGateway，并把临时地址和token作为KMB_AGENT_*传入容器；上游密钥留在宿主。网关观察模型提出的工具调用并控制预算，这些提案不等于已执行动作。正常业务响应原样转发，日志独立脱敏；真实上游密钥回显时拒绝整个响应。真实运行目前只接受已验证的chat_completions路径，裁判另支持responses，详见 [网关协议](model-gateway.md)。

被测模型与裁判可以在不同阶段配置成不同模型，但必须分别记录并固定模型版本、参数、协议、智能体版本和镜像摘要，不能在同一比较批次中无记录更换。doctor只报告主配置或低层适配配置是否存在，不回显密钥。

## 工程验证与人工选型：不同协议

本轮采用 `freeze-engineering`，绑定全部 A/B/C 条件而不选择赢家，`--protocol` 与 `--selection` 互斥。工程协议不要求人工标签，不生成虚构标签，也不充当人审选型清单。v3 的 36 次真实选型、8 项控制及 108 次留出已完成；语义判断未获得独立人工验证。

以下关于人审阈值、获选候选和 `--selection` 的说明仅属于保留的人工选型流程，不是当前工程交付的阻塞条件。两位不同同伴先独立逐判据判断，再处理分歧。自动评分不展示在复核卡中；原始证据仍可能暴露智能体特征，不能过度声称完全盲法。每批复核还绑定当时rubric的内容哈希，判据变化后不能把旧人工标签用于冻结选型。允许口述后由AI或操作员录入，但必须来自实际人的判断；标签上的human_attested只是记录声明，不是自动验证了人的独立性。

比较重点包括自动确定覆盖率、与人工的一致率、关键错误放行、成本与时间。已确认没有模型调用的规则评分记0tokens；发起请求但没有用量回执则记未知。未知费用不能写零；开发集上的结果不能代表selection或holdout。选择阈值应事先确定，样本量不足时不作普遍可靠性结论。

冻结要求完整18题×OpenClaw/Hermes的36次selection运行矩阵，并排除基础设施/执行未知项；不能用一条成功样本冻结。当前代码指纹覆盖包内Python、任务/判据JSON和uv.lock，清单还记录模型、环境及证据。每款智能体的请求模型、返回模型、协议、镜像摘要与智能体版本须可观察且在selection内一致，否则拒绝冻结。

冻结时还会逐份重新计算评分逻辑指纹：字段缺失，或判据、评分源码、提示发生变化，都必须用当前协议重新评分原证据后再冻结。修改评分协议不能让旧评分直接获得新的实验指纹。

每个候选评分版本还冻结 `scorer_version` 与实际使用的裁判请求名、返回名、provider origin、API风格及所有已记录参数。同一候选混用裁判，即使最终不选择该候选，也拒绝冻结。调用裁判且评分成功却缺少身份的记录不能作为已验证配置；明确失败、从未配置的候选可以留在A/B/C比较中，但不能获选。纯规则A无需裁判。

冻结另要求8个预先设计的评分器控制案例。控制包包含原始模拟证据、判据、设计预期和实际评分，预期不是人工标签，也不进入智能体成绩。门禁重新核对控制套件哈希、案例/关键判据数量、实际评分记录、评分指纹，以及获选裁判与selection中的同一配置；错误放行或缺证据仍放行会淘汰候选。v3 的 B/C 真实裁判控制已完成，8 个设计反例逐项匹配，A 在一个语义项明确弃权；这些设计预期不是人工标签，也不构成独立语义准确率证明。运行方法见 README。

当前正式holdout入口要求两款智能体、全部18题、每题3次重复及冻结清单，并检查代码/数据指纹。执行前检查当前请求模型、API协议和本地镜像摘要；执行后再核对实际返回模型与智能体版本等观察条件。发生漂移时保留证据但不接受同条件独立验证结论。holdout只验证已冻结方案，不用于再次挑选赢家。

留出运行的 `manifest.json` 在执行前写入整份选型清单的内容哈希。后续 `score`、`compare` 和 `report` 都要求 `--selection` 及完整的运行根目录；校验108份运行矩阵、清单绑定、执行条件，以及获选评分器的版本/判据指纹。模型裁判在请求前校验配置，返回后再核对实际模型；发现漂移拒绝作为留出验证。已写出的证据和评分保留，不覆盖。

`--variant all` 和三版同时报告仍受支持，但只有冻结获选版本可标为独立验证候选，其余版本明确为探索展示，不能根据留出结果重新选型。`independent_validation.eligible` 仅表示协议绑定检查完成，不代表自动评分准确率或比赛验收达标。获选版存在显式评分错误时可以保留报告，但资格标为 `incomplete`；不能把未完成当成通过。

## 当前不做的事情

不自动提交比赛、不发邮件、不发布仓库、不读取私人申请资料、不向知识库写入。也不以模拟分数制造排行榜、人工标注或平台通过记录。需要下一步验证的项目见 [openKylin验收文档](openkylin-validation.md)。


## 配置冻结与运行中的版本边界

正式选型除了模型名称，还冻结模型提供端origin、完整endpoint的SHA256（不暴露可能含凭据的URL路径）、实际可观察的推理参数、智能体镜像摘要和任务预算。逐次请求数及token量是运行结果，不能作为固定配置；实际返回多个模型时不当作一个已固定模型。

开发阶段边运行边修复时，运行中的进程仍执行已加载版本。源码快照和说明保存在私有运行目录，自动A分数只用于诊断，之后对同一批冻结证据统一重评分。不得把磁盘上修改后的源码指纹当作旧进程已执行新版逻辑的证明。正式selection/holdout期间停止修改协议。

HTML报告中的判据引用可跳转到相应事件、文件、记忆或完整性记录。展开内容都是原证据的只读展示，不会调用智能体或生成新判断。
