# 工程验证协议与结果阅读方式

本项目使用独立的工程验证协议推进 openKylin 长期记忆评测。它固定题目、代码、模型、两款智能体镜像、执行预算、A/B/C 评分条件及受控反例，再对留出集执行真实运行。首个留出批次因模型通道故障不合格；新 v3 批次已完成 108 次真实运行、324 条评分和六维报告，工程协议绑定检查通过。**没有独立人工复核标签，也不选择“人审证明的最佳评分器”。**

## 为什么旧证据不能直接算新版成绩

`data/` 是原始题库；`datasets/engineering-v2/` 仅对有歧义的 `boundary-007` 另立修正版。旧运行和旧评分始终绑定原始题目及规则，不因新题目修订而重新解释。新版必须独立生成 18 题 × OpenClaw/Hermes 各一次的 36 份选型证据，然后以同版 A/B/C 评分、控制题和固定执行条件冻结工程清单。

## 三类证据的用途

| 证据 | 能回答的问题 | 不能推出的结论 |
|---|---|---|
| 受控反例 | 评分器会不会误放预先设计的关键客观错误，能否识别缺证据与错误格式 | 真实场景的总体准确率 |
| 真实选型矩阵 | 两款智能体能否按固定预算完成新题库、三版评分是否有一致条件 | 评分器获得独立人审背书 |
| 冻结后的真实留出矩阵 | 六种能力的客观产物通过率、三版分歧、重复稳定性及故障 | 超出本数据分布的通用可靠性 |

报告的“客观任务通过率”依据文件、状态和可核验动作；执行异常与缺证据另列。模型与规则一致只叫**规则一致率**，不是人工准确率。语义评分必须给出证据引用，仍按未经独立人审处理。每次重复是同一题目的稳定性观察，不增加独立题目数。

## 可复现边界

Mac 用于开发和本地测试。正式平台为 openKylin 3.0 ARM64 Live 主系统及内核；OpenClaw 与 Hermes 在固定 Debian ARM64 容器用户空间运行，不称为原生 openKylin 安装。模型通过客体环回地址与 Mac 上既有代理连接，密钥只在忽略的私有配置中。Live 覆盖层重启会消失，工程、镜像层、报告和证据留在 UUID 绑定的专用 ext4 数据盘；恢复步骤见 [Mac 上的 openKylin 桌面验证环境](openkylin-mac-vm.md)。

当前进展与可核对的产物路径见 [验证状态](validation-status.json) 和 [v3 实验结果](engineering-v3-results.md)。新版 ARM64 安装包已构建并完成断网安装与安装版复评；真实 openKylin 桌面原片、节选及对应的两款智能体演示证据见 [录屏核验](demo-recording-plan.md)。

首个留出执行批次遭遇模型通道中断，108 次运行中的 88 次成为基础设施错误。恢复尝试也因间歇故障停止；新代码版本随后完成两轮不同开发题的双智能体闭环、36份选型证据、108条A/B/C评分及8个设计反例，冻结协议见`../reports/engineering-v3-protocol-20261001.json`。新留出批次在独立目录完成，107次正常结束、1次预算耗尽、0次基础设施或评分错误；旧故障批次仍单独保存，不并入新版成绩。原始故障证据及处理原则见 [留出批次故障记录](engineering-holdout-incident.md)。
