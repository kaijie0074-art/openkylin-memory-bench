# 开发案例：完成运行，不等于交付成功

`update-001` 是开发集中的三会话任务。第一轮约定把正文写入 `old/report.txt`；第二轮正式改为 `current/report.txt`，旧路径废止；第三轮只说“按现行约定”交付 `样机检查完成。`。被测智能体必须跨会话记住更新后的路径，并实际留下内容完全匹配的文件，不能只口头宣称完成。

2026-10-01 在 openKylin 环境中对 OpenClaw 与 Hermes 各运行一次，分别使用独立实验身份；两次原生运行均结束为 `completed`。冻结证据的可信文件盘点却不同：Hermes 留下 `current/report.txt`，内容为 `样机检查完成。`，完整目录清单也确认没有 `old/report.txt`；OpenClaw 没有留下 `current/report.txt`，完整目录清单同样确认没有旧文件。因此 Hermes 的 A/B/C 逐项评分均为通过，OpenClaw 的 `result-1` 在三版中均为失败，`forbidden-file` 均为通过。

| 智能体 | 运行 ID | 最终文件验收 | A/B/C |
|---|---|---|---|
| OpenClaw | `9158e95189854ffca727e24ef4252877` | 缺少 `current/report.txt`；目录盘点完整 | 失败 / 失败 / 失败 |
| Hermes | `753bca0fa9484e36bc517d75ad06becf` | 新路径和正文正确，旧路径不存在；目录盘点完整 | 通过 / 通过 / 通过 |

可在 历史本机实验报告（此批报告未随本轮公开源码或 R1 档案交付） 的“逐项证据与判断”查看判据、理由和引用；报告同目录的 `evidence/<run-id>.json` 是完整冻结证据。报告链接必须连同整个 `report/` 目录保存，否则原始 JSON 的相对链接会失效。模型的口头回答与不可见内部记忆都不能推翻独立采集的文件终态。

这是**开发示例**，每款智能体只运行一次；它证明评测器能在本题上区分“进程完成”和“产物通过”，不能据此估计六维总体能力，也不能证明模型裁判已经得到独立人工验证。正式留出成绩另按冻结协议产生。
