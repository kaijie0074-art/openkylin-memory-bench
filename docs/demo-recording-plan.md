# 真实桌面演示的录制方案

本方案已于 2026-10-02 执行。原始桌面录屏、3 分 27 秒节选与对应两智能体真实运行证据位于 `reports/desktop-recording-final-20261002/` 和 `reports/desktop-demo-real-20261002/`。正式留出验证与人审状态以 `validation-status.json` 为准。

## 内容与顺序

目标成片约3–5分钟，保留连续原始录屏供复核。完整过程超时时可以另做明确标注加速/剪辑的展示版，不能把剪辑版称为未剪辑原始运行，也不能用合成动画或终端文字重放冒充实时评测。

| 画面 | 要说明的内容 | 使用哪份证据 |
|---|---|---|
| openKylin桌面与终端 | 系统、架构、工具版本，Mac虚拟机和容器边界 | 当次现场`/etc/os-release`、内核、`kmb doctor` |
| 一道清楚的小任务 | 旧规则、新规则、最终委托；正确文件与错误文件如何区别 | 开发集update-001，不用尚未揭盲的选型或留出题做教学预演 |
| 启动两款智能体 | 同一模型配置、独立实验身份、多次会话、固定预算 | 一次新的开发演示运行；输出目录新建，不覆盖既有smoke |
| 文件及逐项评分 | 以文件和完整清单判断，不以“已完成”的口头回答判断 | 同一演示运行的原始证据和A/B/C评分 |
| 六维对比雷达图 | 六维成绩、覆盖率、失败/未知、评分成本，注明样本量 | 已完成并允许展示的真实矩阵；单题演示不冒充六维验证 |
| 收尾 | 能证明什么、仍不能证明什么、如何复现 | 冻结清单、源/依赖版本、报告路径与已知限制 |

单题演示与完整矩阵汇总必须分别标注批次与样本量，例如“现在演示一题；接着读取已冻结的完整矩阵证据生成六维报告”。不暗示后面的全部结果均来自刚才那一题。

## 录制前检查

- 先完成工程验证协议的冻结及真实矩阵采集。演示使用已核验的真实证据，并明确语义评分未经独立人工验证；旧人工校准流程保留为后续研究路径。
- 只展示专用openKylin桌面和项目产物。模型配置通过已有私有环境传入，不在终端显示`.env`、Authorization或真实密钥。
- 记录源码/协议、智能体镜像、模型身份、任务与配置，确认存储余量；不要在录制中临时升级或更换模型。
- 录屏工具由 AI 操作，用户无需鼠标键盘。正式录制使用经短片预检的 `wf-recorder`。
- UI操作与画面采集通过允许的桌面工具完成。遇到工具访问限制，不通过另一个服务地址或后台抓屏绕过。

## 文件验收

录制完成后必须实际检查：文件可解码、时长/帧率/分辨率有效，开头/中段/结尾均有真实画面，无黑屏、丢失运行过程或凭据曝光；视频中展示的运行ID、模型、样本量及评分须与原始JSON核对。登记原始视频与成片的SHA256，并保留剪辑/加速说明。

技术上正常结束但任务失败也可以成为演示内容。它能展示评测器如何识别错误，不能剪去失败片段后宣称智能体全部通过。成片必须明确独立人审、最终留出或冷恢复各自的实际状态；只有实际完成后才使用相应结论。

当前不执行上传、公开发布、投稿或联系主办方；本文件不构成这些动作的授权。

可讲解的开发案例现已具备真实闭环：`reports/engineering-v3-gateway-status-smoke-20261001/` 的 `update-001` 中，Hermes 的真实运行 `753bca0fa9484e36bc517d75ad06becf` 在 A/B/C 均通过，OpenClaw 的 `9158e95189854ffca727e24ef4252877` 在三版均失败；两者执行状态均为 `completed`。报告在该目录的 `report/index.html`，适合在桌面上展示“运行完成”与“任务验收通过”是不同的判断。另一个 `boundary-001` 开发案例在 `reports/engineering-v3-boundary-smoke-20261001/`，两款智能体均完成且三版通过。两组均是开发演示资料，不冒充正式留出成绩。
