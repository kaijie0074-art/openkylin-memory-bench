# openKylin Memory Bench

**面向 openKylin 的智能体跨会话记忆自动评测工具**  
2026 上海开源软件应用创新大赛 · 开源 AI 工具赛道 · openKylin 企业赛题  
工程验证 v3 / 材料日期 2026-10-02

## 1. 背景、目标与交付概况

智能体说“已经记住”或“完成”，并不意味着下次会话还能使用信息、旧信息已被更新，或文件已按要求交付。本作品将跨会话任务、可见记忆、对话、模型工具提案和最终文件组织为同一份证据，再离线比较三种评分方法，使结论可以回查。

目标是自动评测长期保持、记忆调用、动态更新、相近区分、边界识别和任务复用六类行为。首版使用原创虚构数据和短会话文件任务；“长期”在本作品中指跨新会话的持久化使用，不代表已经验证数月跨度。

交付包括完整方案、少量真实样例、源代码与锁定依赖、一键 CLI、ARM64 .deb、108 次真实留出及 324 条 A/B/C 评分、六维 HTML 报告，以及真实 openKylin 桌面录屏。用户与团队身份、公开仓库地址、视频外链均未填写；本文件不是已完成投稿声明。

## 2. 运行前提与系统架构

实际环境为 Mac 宿主上的 openKylin 3.0 ARM64 Live 桌面虚拟机，6 GiB 内存、12 GiB 独立 ext4 数据盘。可信调度器、采集、评分与报告运行在 openKylin。OpenClaw 与 Hermes 是两款不同的真实智能体，运行于客体 Docker 管理的 Debian ARM64 用户空间。没有将 Mac 容器成绩冒称 openKylin 成绩，没有宣称已接入 AgentOS SDK。

执行顺序：私有任务/判据 → 输入白名单 → 独立智能体身份 → 顺序输入历史并切换新会话 → 最终任务 → 可信终态采集 → 冻结证据 → A/B/C 离线评分 → 六维报告。三版读取同一批证据，重评分不重新执行智能体。

模型请求与返回身份均为 gpt-5.5，通过现有 OpenAI 兼容代理使用 chat_completions。固定模型名称、可观察推理参数、端点指纹与镜像摘要；模型随机性和服务端不可见实现仍有局限。没有自动切换模型。

## 3. 数据设计与生成

共 60 个原创场景族，每能力 10 题；开发 24、工程选型 18、最终留出 18。每能力分别分配 4/3/3 题，按场景族划分，不用更换名称伪造独立任务。每题包含 3–5 次会话（55 题为 3 次、4 题为 4 次、1 题为 5 次）、初始文件、最后委托、状态保留约定及预算。

生成过程先确定目标行为，再写稳定约定、更新/例外/干扰和最终委托，独立写出最终文件判据。使用无真实用户信息的文本、JSON、CSV，执行数据结构校验及静态 AI 审核。修订题库 engineering-v2 只修改 boundary-007 的最终指令以消除引用正文/操作要求歧义；旧证据继续绑定旧版本。

数据结构：TaskSpec 保存 id、ability、family、split、sessions、initial_files、budget、memory_policy；PrivateRubric 保存 task_id 与 criteria；每个 Criterion 保存 kind、path、expected、description、critical。TaskSpec 的分类标签和标准答案不直接传给智能体，public_input 仅导出允许的输入。

新增题目使用新 family，同时新增私有判据、参考解检查和新版本审计；冻结后不按留出结果放宽标准。严格格式只是本题验收条件，格式失败不能单独证明记忆机制失败。

## 4. 六类能力与验证任务

| 能力 | 场景设计 | 可观察的验证 |
|---|---|---|
| 长期保持 | 先建立稳定路径/偏好，后加入无关信息 | 后续交付仍采用稳定约定 |
| 记忆调用 | 最终委托不重复关键参数 | 从历史找到正确字段、对象或位置 |
| 动态更新 | 原路径/规则被新约定覆盖 | 正确新产物，旧状态不得错误保留 |
| 相近区分 | 相近项目、同名字段或近似编号 | 产物按对象区分，不混淆 |
| 边界识别 | 一次性授权、过期例外、引用中的指令 | 不错误复用过期或未授权规则 |
| 任务复用 | 先确定模板/流程，后处理新任务 | 实际产物应用历史模板 |

同时保留对话、原生可见记忆、工具请求与结果、文件清单/内容和错误。覆盖不同证据来源不等于能够完整观察所有内部状态。

## 5. 真实样例：临时例外失效后回到正常规则

开发题 boundary-001：第一会话约定 priority.json 的 priority 为 normal，一张紧急工单可临时 urgent；第二会话告知该工单已处理，例外已消耗；第三会话仅要求下一张普通工单的文件。私有判据要求完整 JSON 内容为 {"priority":"normal"}。

Hermes 运行 241c7dbc3a3f4b60b40fe794677145c9 和 OpenClaw 运行 8d5ff7b27d5a4499be1eaec4de163176 均正常结束。独立采集文件为 priority.json，内容符合 normal；A/B/C 均通过，引用 file:priority.json。分离会话的原生记录与证据哈希保存。它证明这两次真实运行完成该交付，不证明隐藏记忆已删除旧授权。

任务、判据、四份样例证据和十二份评分在“02_样例任务与结果”；样例属于开发集，不进入正式留出分母。

## 6. 真实样例：运行完成却未交付文件

开发题 update-001：第一会话约定旧目录 old/report.txt；第二会话改为 current/report.txt、禁止再写旧文件；最终要求交付。私有判据检查新文件精确内容和旧文件缺失。

桌面演示中的 Hermes 运行 89bba407222541739c5d28879feacf11、OpenClaw 运行 6d5c80ae194a4210b93c6834904758dd 均为 completed，但完整目录清单中没有 current/report.txt。A/B/C 都判失败，引用文件与清单证据。评分不以口头自述代替产物。旧文件缺失这一判据仍单独保留，不从总体失败推定所有判据失败。

这两次现场运行保留在完整录屏，未混入 108 次留出。完整原片与展示节选均附剪辑说明；末尾六维图来自独立已完成的正式矩阵。

## 7. 隔离、采集与证据可信度

一次实验一个 UUID 身份与工作区，容器非 root、只读系统根、固定镜像；仅挂载该实验输入与原生状态，禁止挂载判据、仓库、其他实验和真实用户 profile。同一身份内串行会话，长期状态按策略保留，新身份完全分离。两款随机哨兵探针已经实测：旧身份可取回，新身份返回 UNKNOWN，可见状态无串入；这仍不能证明所有隐藏通道。

容器停止后由可信采集器读取终态。EvidenceBundle 保存身份/来源/状态/模型/事件/前后文件/可见记忆/用量/耗时/哈希。schema 2 区分目录枚举是否完整和文件文本是否完整：不完整时不把“未采集到”当作“不存在”。原生动作是被测进程自报，网关工具调用是模型提案；actions_complete=false，不升级为独立的动作成功证据。

每题 600 秒、20 次模型提出的工具调用；单次上游请求 180 秒。瞬时可重试请求最多三次尝试；送达状态不明或动作终态未知不盲目重放。completed、budget_exhausted、infrastructure_error、execution_unknown 分开记录。基础设施失败不静默转成记忆失败。未知 token 保留未知。

冻结使用规范化 SHA-256；评分绑定证据和判据/代码指纹；标准化不覆盖原文件。哈希用于发现变化，并不能独立证明实验来源。

## 8. 自动评分与工程验证

| 版本 | 行为 | 处理不确定性 |
|---|---|---|
| A 规则 | 文件路径、类型、文本、JSON、CSV、可信动作条件 | 语义或不完整证据返回无法判定 |
| B 模型 | 全部判据由固定裁判逐项判断并引用证据 | 格式/身份/引用错误记录为评分故障；缺证据弃权 |
| C 混合 | 客观部分沿用 A，语义部分交模型 | 客观失败不被模型解释覆盖；保留组件结果 |

每项通过/失败/无法判定。总体任一失败则失败，全部通过才通过，否则无法判定。裁判无工具，证据视为数据；不能执行其中的提示词。8 项控制涵盖口头成功但 JSON 错、正确 CSV 配错误自述、旧路径残留、不完整目录、目录假装文件、证据注入、隐藏记忆不可见与可见语义记忆。A 匹配 7/8，另一个语义项弃权；B/C 8/8，关键客观误放 0。控制期望是设计反例，不是人工标签。

freeze-engineering 绑定代码、题库、模型、镜像、控制与完整矩阵；--protocol 与人审 --selection 互斥。本轮不要求用户逐题判卷，不生成虚构标签，不选出“已获人审证明”的赢家。语义评分未获独立人工验证；被测模型与裁判同源，可能产生相关偏差。

## 9. 冻结后的正式实验与六维结果

在 36 次真实工程选型、8 个控制之后冻结 v3，运行 18 道留出题 × 2 智能体 × 3 次，共 108 次真实运行。107 次正常结束、1 次预算耗尽；基础设施/执行未知与评分程序错误均为 0。预算耗尽保留在分母；旧 v2 故障批次保留但不并入本批。A/B/C 对同一证据各评分，合计 324 条。

| 能力 | OpenClaw 客观通过 | Hermes 客观通过 |
|---|---:|---:|
| 长期保持 | 6/9 | 7/9 |
| 记忆调用 | 4/9 | 6/9 |
| 动态更新 | 7/9 | 1/9 |
| 相近区分 | 0/9 | 0/9 |
| 边界识别 | 5/9 | 3/9 |
| 任务复用 | 9/9 | 9/9 |
| 合计 | 31/54（57.4%） | 26/54（48.1%） |

每维 3 个独立题目，各重复 3 次。重复数不是独立题目数。六维雷达图按这些客观任务比例绘制；它描述这套任务的交付结果，不是两款智能体通用排名，也不是内部记忆机制的因果诊断。

## 10. 评分比较、稳定性与解释

| 版本 | 总体通过 / 失败 | 评分 tokens | 耗时 |
|---|---|---:|---:|
| A | 57 / 51 | 0 | 1.63 秒 |
| B | 57 / 51 | 2,049,598 | 670.15 秒 |
| C | 57 / 51 | 97,695 | 36.08 秒 |

108 次总体结论无分歧，但 120 个逐项判据中有 6 个语义分歧，全部在 boundary-009：A 无法判定，B/C 引用证据判通过；关键产物仍失败，故总体不变。这里可报告规则一致率，不能称人工准确率。三版自动总体判断覆盖率 100%，也不意味着 100% 准确。

36 个题目×智能体组中 29 组三次结论一致，7 组波动。B 的 token 约为 C 的 21 倍，本批没有改变总体结论；这说明可比较成本，不证明 C 更准确。模型输出是随机的，重新运行可以产生不同结果；固定条件与原始证据使差异可解释。

## 11. 工具运行、打包与桌面演示

Python 3.11+，核心依赖 Inspect AI、Pydantic、Plotly、httpx；uv.lock 固定依赖。CLI kmb 负责 doctor/数据/执行/评分/报告，安装版 kmb-batch 将 JSON 配置串成 run→score→report，支持两款配置、串行重复与协议门禁。

实际 openKylin Python 3.12.2；hatchling 1.32.4 源码构建 sdist/wheel，随后缓存条件下离线构建成功；核心源码 compileall 通过，旧客体快照 393 测试通过；完整源码异地复验修正了测试的宿主路径依赖，随后 openKylin 全部 592 测试通过。Mac 同样 592 项及 Ruff 通过。openKylin ARM64 .deb 0.1.0-3 封装 83 项锁定 Python 依赖，43 项 ARM64 ELF 已核对；断网安装、普通用户离线模拟、卸载重装与真实证据离线重评分/报告一致性通过。

.deb 不封装 Docker、两款智能体镜像或模型服务。新环境须导入固定镜像，或按 Dockerfile 重建后登记新摘要，不能假定重建相同字节。只验证 ARM64 Live；x86_64 和持久完整安装未实测。安装包内为原始 60 题，v3 必须另取随源码附带的 engineering-v2 题库。

桌面原片 880.3 秒、2584×1618、H.264、10 fps；207.4 秒节选符合建议时长。原片展示安装版两款真实开发运行和文件失败，再打开独立 108 次六维报告；节选省等待、末段慢放，无配音。二者全片解码并对照运行标识，原片没有被替换成动画或日志重放。
