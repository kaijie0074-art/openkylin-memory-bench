# openKylin Memory Bench · 评审复现说明

本交付评测的是两款真实智能体的跨会话行为；短会话任务不等同于经过数月时间的长期保持。实际成绩来自 openKylin 3.0 ARM64 Live 桌面客体；评测 CLI 和采集器运行在 openKylin，智能体进程运行在该系统 Docker 管理的 Debian ARM64 用户空间。未宣称智能体直接使用 openKylin 用户空间或已接入 AgentOS SDK。开发与录制操作由 Mac 完成，Mac 成绩不用于代替客体成绩。

## 先查看已有结果

1. 打开 `04_正式实验报告/结果摘要.md`，再打开完整交付中的 `04_正式实验报告/report/index.html`。保留同目录 `evidence/`，链接才有效。
2. `02_样例任务与结果/` 给出两道开发题、四份真实证据与十二份 A/B/C 评分，包括交付成功与交付失败。数据、证据和评分是原文件的副本，未改写历史。
3. `06_演示视频/展示节选.mp4` 用于快速观看。`完整原片.mp4` 是连续真实桌面采集，880.3 秒；任务书的 3-5 分钟为建议时长。207.4 秒节选省去等待，末段三倍慢放，不能当作连续执行证明。

## 在 openKylin 运行核心流程

当前验证架构为 ARM64；x86_64 上的依赖与智能体镜像需要另行构建验证。Windows 不是本交付的执行环境。

安装随附 ARM64 软件包：

```sh
sudo dpkg -i openkylin-memory-bench_0.1.0-3_arm64.deb
kmb doctor
```

确认 doctor 输出中的系统为 openkylin、架构为 aarch64。在已准备源码依赖的环境中，还可运行 `bash scripts/validate-openkylin.sh` 检查实际系统身份。

将源码 ZIP 或 tar.gz 解压到普通用户可写的新目录。Linux 推荐源码 tar.gz 保留脚本执行位；ZIP 须使用保留 Unix 权限的解压工具，Python zipfile 默认不恢复这些执行位。安装包只内置原始 60 题；本轮冻结题库在解压后的 `datasets/engineering-v2`，所有命令须显式使用它。源码工作区也可通过 `uv sync --frozen --group dev` 安装，然后 `uv run kmb` 或 `uv run python -I scripts/run-benchmark.py` 执行。

先检查离线编排：

```sh
kmb-batch --config examples/competition/offline-check.json --output reports/reviewer-offline-check --dry-run
kmb-batch --config examples/competition/offline-check.json --output reports/reviewer-offline-check
```

它不调用模型，只验证流水线；生成的模拟记录不可进入真实成绩。输出目录必须尚不存在。软件包的 Python 依赖已封装，Docker、两款智能体镜像及模型服务不在 .deb 中。

## 准备真实智能体与模型

必要条件是可用 Docker、独立运行 UID 10001、两款固定镜像以及支持工具调用的 OpenAI 兼容服务。已有镜像摘要与版本见 `competition/冻结运行环境.json`；新环境需从已保存镜像导入相同摘要，或按 `containers/` 固定上游版本重新构建并记录新摘要。Dockerfile 的上游系统包与传递依赖未全锁定，重建不能声称得到相同镜像。实际证据也不可能在随机模型服务下逐字重现。

模型配置从调用进程显式提供 `KMB_BASE_URL`、`KMB_API_KEY`、`KMB_MODEL`、`KMB_API_STYLE`，本轮固定 `KMB_UPSTREAM_TIMEOUT_SECONDS=180`。openKylin 3.0 的系统 Docker CLI 位于 `/opt/system/bin`；如 PATH 未包含该目录，按实际安装位置加入后再次运行 doctor，不能把路径缺失当作 Docker 已安装可用。`.env.example` 是字段说明，未含可用密钥；工具不会搜索本机其他应用的凭据。原实验请求及回执为 `gpt-5.5`。旧服务 endpoint 指纹已经冻结，不能用另一服务运行后仍宣称是同一个冻结实验。

```sh
kmb-batch --config examples/competition/development.json --output reports/reviewer-real-development --dry-run
kmb-batch --config examples/competition/development.json --output reports/reviewer-real-development
```

这条命令顺序完成两款智能体的多会话运行、同证据 A/B/C 评分及 HTML 报告。预算为每题 600 秒、20 次模型提出的工具调用；提出调用不证明工具已执行。独立文件终态可核验，原生动作轨迹和隐藏记忆的不完整性仍如实保留。

若镜像或模型条件发生变化，先在开发集验证，再建立新的选型、控制测试和工程冻结协议；原留出结果继续保留。`holdout-reference.json` 描述原矩阵，只有原服务、原镜像和协议条件实际匹配时才能复跑；不提供绕过门禁的命令。

## 离线核对已有真实证据

完整证据档案解压后保留 `reports/` 目录结构。以下命令只调用规则评分器，不请求模型，不重跑智能体：

```sh
kmb --dataset datasets/engineering-v2 score \
  --evidence reports/engineering-v3-holdout-20261001/runs \
  --variant A --protocol reports/engineering-v3-protocol-20261001.json \
  --output reports/reviewer-holdout-rules
kmb --dataset datasets/engineering-v2 report \
  --evidence reports/engineering-v3-holdout-20261001/runs \
  --scores reports/engineering-v3-holdout-20261001/scores \
  --protocol reports/engineering-v3-protocol-20261001.json \
  --output reports/reviewer-holdout-report
```

B/C 评分可直接阅读冻结记录；重新调用裁判需要同协议模型配置，并产生新的评分记录。协议校验只证明条件绑定和矩阵完整，不等于人工准确率验证。正式结果有 107 次正常结束和 1 次预算耗尽，基础设施或评分程序错误均为 0；不得删去预算耗尽记录。

## 源码构建与检查

Python 项目可在 openKylin 客体用 `uv build` 构建 sdist 和 wheel；本次先安装构建依赖，再离线构建成功。完整源码在新目录的 592 项测试通过，发现并修正的仅为测试中原宿主绝对路径依赖，不修改冻结题目或评分协议。已有运行环境可供离线复验；全新源码环境未预缓存所有 wheel，uv sync 需要网络或另行提供 wheel，不能据此称源码全离线安装。核心源码及 Python 脚本在客体 `compileall` 编译通过。运行依赖由 `uv.lock` 固定；构建依赖版本与测试记录见 `07_验收记录/`。Mac 虚拟机管理、Windows 探针等是可选宿主辅助脚本，不属于 openKylin 评测运行必需代码。

保持数据、判据、代码和证据的原始版本。新增任务采用新 family，并重新分配集合；证据中的标准答案只属于评分端，不能挂载给被测智能体。
